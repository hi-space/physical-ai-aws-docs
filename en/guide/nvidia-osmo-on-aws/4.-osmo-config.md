# 4. OSMO Configuration

Configure the system via OSMO CLI. Define how OSMO accesses S3, where to store workflow logs, and which GPU platforms to use.

**Configuration Flow:**

```
Create IAM User → Register Credential → Set Config → Create Queue
                 (S3 access key)     (storage path)  (GPU quota)
```

**Runtime Behavior:** Credentials and Config are used during workflow execution as follows:
- **Credential** (4.3): OSMO injects this key when workflow Pods read/write data to S3
- **Config WORKFLOW** (4.4): ctrl sidecar uses this to determine where to store workflow logs and outputs on S3
- **Config SERVICE**: ctrl sidecar reports job completion/failure status to this internal URL
- **Config POOL**: Maps workflow `platform` field to GPU node schedules
- Running workflows without credentials results in `Workflow data credential is not set` error

### 4.1 OSMO CLI Login

```bash
# Port-forward — enables local access to OSMO API via kubectl
kubectl port-forward -n osmo-minimal svc/osmo-service 9001:9001 &

# dev-login — convenient login for development (production uses OAuth)
osmo login --url http://localhost:9001 --dev-login
```

{% hint style="info" %}
After login, connection information is saved to `~/.config/osmo/login.yaml`.
{% endhint %}

### 4.2 Create IAM User for S3 Access

**Why is this needed?** OSMO workflows read training data from S3 and store workflow logs. A dedicated IAM user with Access Keys is required.

```bash
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
BUCKET_NAME=$(aws s3api list-buckets \
  --query "Buckets[?starts_with(Name,'osmo-data')].Name" --output text)

echo "S3 Bucket: $BUCKET_NAME"

# Create OSMO-specific IAM user
aws iam create-user --user-name osmo-workflow-user

# Grant S3 access and SimulatePrincipalPolicy permissions
# (OSMO validates access permissions with SimulatePrincipalPolicy during credential registration)
aws iam put-user-policy --user-name osmo-workflow-user \
  --policy-name osmo-s3-access \
  --policy-document "{
    \"Version\": \"2012-10-17\",
    \"Statement\": [
      {
        \"Effect\": \"Allow\",
        \"Action\": [\"s3:*\"],
        \"Resource\": [
          \"arn:aws:s3:::${BUCKET_NAME}\",
          \"arn:aws:s3:::${BUCKET_NAME}/*\"
        ]
      },
      {
        \"Effect\": \"Allow\",
        \"Action\": [\"iam:SimulatePrincipalPolicy\"],
        \"Resource\": \"arn:aws:iam::${ACCOUNT_ID}:user/osmo-workflow-user\"
      }
    ]
  }"

# Generate Access Key
aws iam create-access-key --user-name osmo-workflow-user
```

{% hint style="warning" %}
Save the output `AccessKeyId` and `SecretAccessKey`. You will need them in subsequent steps.

There may be a propagation delay (~10 seconds) after IAM user creation. If the next step fails, retry after a brief wait.
{% endhint %}

### 4.3 Register OSMO Credential

**Why is this needed?** Once you register S3 access keys with OSMO, workflows automatically use these credentials to read and write data.

```bash
osmo credential set DATA \
  --type DATA \
  --payload \
    access_key_id=YOUR_ACCESS_KEY_ID \
    access_key=YOUR_SECRET_ACCESS_KEY \
    endpoint=s3://${BUCKET_NAME} \
    region=us-west-2
```

{% hint style="info" %}
Replace `YOUR_ACCESS_KEY_ID` and `YOUR_SECRET_ACCESS_KEY` with values generated in step 4.2.
{% endhint %}

### 4.4 OSMO Configuration

**Why is this needed?** OSMO controls behavior through multiple configuration files:
- **WORKFLOW** — Where to store workflow execution data and logs
- **DATASET** — Training dataset bucket paths
- **SERVICE** — Internal communication URL (ctrl sidecar → logger)
- **POOL** — GPU platform definitions

```bash
# WORKFLOW config — workflow execution data and log storage paths
cat > /tmp/workflow-config.json <<EOF
{
  "workflow_data": {
    "credential": {
      "endpoint": "s3://${BUCKET_NAME}/workflows",
      "region": "us-west-2",
      "access_key_id": "YOUR_ACCESS_KEY_ID",
      "access_key": "YOUR_SECRET_ACCESS_KEY"
    },
    "websocket_timeout": 1440,
    "data_timeout": 10,
    "download_type": "download"
  },
  "workflow_log": {
    "credential": {
      "endpoint": "s3://${BUCKET_NAME}/logs",
      "region": "us-west-2",
      "access_key_id": "YOUR_ACCESS_KEY_ID",
      "access_key": "YOUR_SECRET_ACCESS_KEY"
    }
  }
}
EOF
osmo config update WORKFLOW --file /tmp/workflow-config.json

# DATASET config — S3 path where training datasets are stored
cat > /tmp/dataset-config.json <<EOF
{
  "buckets": {
    "osmo": {
      "dataset_path": "s3://${BUCKET_NAME}/datasets",
      "region": "us-west-2",
      "mode": "read-write"
    }
  },
  "default_bucket": "osmo"
}
EOF
osmo config update DATASET --file /tmp/dataset-config.json

# SERVICE config — URL where ctrl sidecar reports status
# ctrl sidecar runs inside each workflow Pod and reports job completion/failure status to this URL
cat > /tmp/service-config.json <<EOF
{
  "service_base_url": "http://osmo-logger.osmo-minimal.svc.cluster.local"
}
EOF
osmo config update SERVICE --file /tmp/service-config.json

# POOL config — Define available GPU platforms
cat > /tmp/pool-config.json <<EOF
{
  "pools": {
    "default": {
      "name": "default",
      "description": "Default pool",
      "status": "ONLINE",
      "backend": "default",
      "default_platform": "gpu-train",
      "common_pod_template": ["default_ctrl", "default_user"],
      "platforms": {
        "gpu-train": {
          "description": "GPU training platform (L40S)",
          "default_variables": {"USER_GPU": 1}
        },
        "gpu-sim": {
          "description": "GPU simulation platform (A10G)",
          "default_variables": {"USER_GPU": 1}
        }
      }
    }
  }
}
EOF
osmo config update POOL --file /tmp/pool-config.json
```

{% hint style="info" %}
Replace `YOUR_ACCESS_KEY_ID` and `YOUR_SECRET_ACCESS_KEY` with actual values.
{% endhint %}

### 4.5 Create Kai Scheduler Queue

**Why is this needed?** Kai Scheduler manages GPU resource quotas via Queue CRDs. Without a Queue, workflows fail with `QueueDoesNotExist` error.

Queue names follow the pattern `osmo-pool-{workflow_namespace}-{pool_name}`.

```bash
kubectl apply -f - <<'EOF'
apiVersion: scheduling.run.ai/v2
kind: Queue
metadata:
  name: osmo-pool-osmo-workflows-default
  namespace: kai-scheduler
spec:
  parentQueue: default
  priority: 100
  resources:
    gpu:
      quota: 4
      limit: 8
    cpu:
      quota: 48000
      limit: 96000
    memory:
      quota: 192000000000
      limit: 384000000000
EOF
```

{% hint style="info" %}
CPU and memory units are millicores and bytes. 48000 = 48 cores, 192000000000 ≈ 192GB.
{% endhint %}

### Troubleshooting

| Symptom | Cause | Solution |
|---------|-------|----------|
| `Workflow data credential is not set` | Credential not configured | Run step 4.3 |
| `QueueDoesNotExist` | Kai Queue not created | Run step 4.5 |
| `InvalidClientTokenId` | IAM key propagation delay | Retry after 10 seconds |
| `SimulatePrincipalPolicy` error | Missing IAM policy | Verify step 4.2 policy includes this permission |
| OSMO CLI 404 | Incorrect port-forward | Verify `svc/osmo-service` port 9001 |
