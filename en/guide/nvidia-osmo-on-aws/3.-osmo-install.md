# 3. OSMO Installation (Helm)

OSMO consists of multiple microservices. Use Helm charts to deploy these services to Kubernetes.

**OSMO Architecture:**

```
┌─ osmo-minimal namespace ────────────────────────────┐
│  osmo-service  — CLI/API endpoints                  │
│  osmo-agent    — Internal job coordination          │
│  osmo-logger   — Workflow log collection (ctrl)     │
│  osmo-worker   — Background job processing          │
└─────────────────────────────────────────────────────┘
┌─ osmo-operator namespace ───────────────────────────┐
│  backend-operator — Workflow Pod creation/mgmt      │
└─────────────────────────────────────────────────────┘
┌─ kai-scheduler namespace ───────────────────────────┐
│  kai-scheduler — NVIDIA GPU scheduler               │
│  (Manages GPU quotas via Queue CRDs)                │
└─────────────────────────────────────────────────────┘
┌─ osmo-workflows namespace ──────────────────────────┐
│  (User workflow Pods run here)                      │
└─────────────────────────────────────────────────────┘
```

---

### 3.1 Namespace Creation

Create Kubernetes namespaces where each component will run:

```bash
kubectl create namespace osmo-minimal
kubectl create namespace osmo-operator
kubectl create namespace osmo-workflows
```

---

### 3.2 Add Helm Repository

Register the NVIDIA NGC registry to access OSMO Helm charts:

```bash
helm repo add osmo https://helm.ngc.nvidia.com/nvidia/osmo \
  --username '$oauthtoken' --password "${NGC_API_KEY}"
helm repo update
```

{% hint style="warning" %}
`NGC_API_KEY` must be set as an environment variable. Obtain it from the [NGC Portal](https://org.ngc.nvidia.com/).
{% endhint %}

---

### 3.3 Infrastructure Endpoint Discovery

Retrieve the RDS and Redis endpoints created by CDK. OSMO needs these to connect to the databases:

```bash
POSTGRES_HOST=$(aws rds describe-db-instances \
  --query "DBInstances[?DBInstanceIdentifier=='osmo-postgres'].Endpoint.Address" \
  --output text --region us-west-2)

REDIS_HOST=$(aws elasticache describe-replication-groups \
  --query "ReplicationGroups[?ReplicationGroupId=='osmo-redis'].NodeGroups[0].PrimaryEndpoint.Address" \
  --output text --region us-west-2)

echo "PostgreSQL: $POSTGRES_HOST"
echo "Redis: $REDIS_HOST"
```

---

### 3.4 Kubernetes Secrets Creation

**Why is this needed?** Sensitive information like database passwords should not be stored directly in Helm values. Instead, manage them as Kubernetes Secrets that Pods reference at runtime.

```bash
# PostgreSQL access password
kubectl create secret generic db-secret \
  --from-literal=db-password="YOUR_DB_PASSWORD" \
  --namespace osmo-minimal

# Redis access password
kubectl create secret generic redis-secret \
  --from-literal=redis-password="YOUR_REDIS_PASSWORD" \
  --namespace osmo-minimal

# Master Encryption Key (MEK) — Used for OSMO internal token encryption
MEK_KEY=$(openssl rand -base64 32 | tr -d '\n')
kubectl apply -f - <<EOF
apiVersion: v1
kind: ConfigMap
metadata:
  name: mek-config
  namespace: osmo-minimal
data:
  mek.yaml: |
    currentMek: key1
    meks:
      key1: '{"k":"${MEK_KEY}","kid":"key1","kty":"oct"}'
EOF
```

{% hint style="info" %}
Use the `YOUR_DB_PASSWORD` and `YOUR_REDIS_PASSWORD` values specified during CDK deployment in `cdk.json` or as environment variables.
{% endhint %}

---

### 3.5 NGC Pull Secret Creation

**Why is this needed?** OSMO container images are hosted on NVIDIA's private registry (nvcr.io). Kubernetes needs authentication credentials to pull images.

```bash
# OSMO service namespace
kubectl create secret docker-registry nvcr-secret \
  --namespace osmo-minimal \
  --docker-server=nvcr.io \
  --docker-username='$oauthtoken' \
  --docker-password="${NGC_API_KEY}"

# Workflow namespace (workflow Pods also pull OSMO init-container)
kubectl create secret docker-registry nvcr-secret \
  --namespace osmo-workflows \
  --docker-server=nvcr.io \
  --docker-username='$oauthtoken' \
  --docker-password="${NGC_API_KEY}"
```

---

### 3.6 OSMO Service Deployment

Deploy core OSMO services. Pass RDS/Redis connection information via values file:

```bash
cat > /tmp/service_values.yaml <<EOF
global:
  osmoImageLocation: nvcr.io/nvidia/osmo
  osmoImageTag: latest
  imagePullSecret: nvcr-secret

services:
  configFile:
    enabled: true

  postgres:
    enabled: false
    serviceName: ${POSTGRES_HOST}
    port: 5432
    db: osmo
    user: postgres
    passwordSecretName: db-secret
    passwordSecretKey: db-password

  redis:
    enabled: false
    serviceName: ${REDIS_HOST}
    port: 6379
    tlsEnabled: true

  agent:
    scaling:
      minReplicas: 1
      maxReplicas: 1

  logger:
    scaling:
      minReplicas: 1
      maxReplicas: 1

podMonitor:
  enabled: false
EOF

helm install osmo-minimal osmo/service \
  --namespace osmo-minimal \
  --values /tmp/service_values.yaml \
  --wait --timeout 10m
```

{% hint style="info" %}
`postgres.enabled: false` and `redis.enabled: false` mean "OSMO should not deploy its own DB/Redis, but instead use external instances created by CDK."
{% endhint %}

### 3.7 Backend Operator Deployment

**Why is this needed?** Backend Operator creates actual Kubernetes Pods when users submit workflows. It requires an authentication token to communicate with OSMO Service.

```bash
# Connect to OSMO Service and generate operator token
kubectl port-forward service/osmo-service 9001:9001 -n osmo-minimal &
sleep 5

# Install and login to OSMO CLI
pip install nvidia-osmo
osmo login --url http://localhost:9001 --dev-login

# Create service token for Backend Operator
OPERATOR_TOKEN=$(osmo token set backend-token \
  --expires-at 2027-01-01 \
  --description "Backend Operator Token" \
  --service \
  --roles osmo-backend \
  -t json | jq -r '.token')

kill %1  # End port-forward

# Save token as Kubernetes Secret
kubectl create secret generic osmo-operator-token \
  --from-literal=token="${OPERATOR_TOKEN}" \
  --namespace osmo-operator

# Deploy Operator
cat > /tmp/operator_values.yaml <<EOF
global:
  osmoImageLocation: nvcr.io/nvidia/osmo
  osmoImageTag: latest
  accountTokenSecret: osmo-operator-token
  agentNamespace: osmo-operator
  backendName: default
  backendNamespace: osmo-workflows
  loginMethod: token
  serviceUrl: http://osmo-agent.osmo-minimal.svc.cluster.local

podMonitor:
  enabled: false

sidecars:
  otel:
    enabled: false
EOF

helm install osmo-operator osmo/backend-operator \
  --namespace osmo-operator \
  --values /tmp/operator_values.yaml \
  --wait --timeout 5m
```

### 3.8 Kai Scheduler Installation

**Why is this needed?** NVIDIA Kai Scheduler fairly distributes GPU resources when multiple workflows request GPUs simultaneously. Queue CRDs allow setting GPU quotas per team or project.

```bash
helm install kai-scheduler osmo/kai-scheduler \
  --namespace kai-scheduler --create-namespace \
  --version 0.13.4
```

### 3.9 Verify Deployment

Check Helm releases and Pod status:

```bash
# Verify Helm releases — all three charts should show deployed status
helm list --all-namespaces
```

**Expected output:**

```
NAME             NAMESPACE       STATUS     CHART
osmo-minimal     osmo-minimal    deployed   service-x.x.x
osmo-operator    osmo-operator   deployed   backend-operator-x.x.x
kai-scheduler    kai-scheduler   deployed   kai-scheduler-0.13.4
```

```bash
# OSMO service Pods (5 total)
kubectl get pods -n osmo-minimal
```

**Expected output:**

```
NAME                                        READY   STATUS    AGE
osmo-agent-xxx                              2/2     Running   2m
osmo-delayed-job-monitor-xxx                1/1     Running   2m
osmo-logger-xxx                             2/2     Running   2m
osmo-service-xxx                            2/2     Running   2m
osmo-worker-xxx                             1/1     Running   2m
```

```bash
# Kai Scheduler
kubectl get pods -n kai-scheduler

# Backend Operator
kubectl get pods -n osmo-operator
```

{% hint style="warning" %}
If any Pod is not Running, check events with `kubectl describe pod <pod-name> -n <namespace>`.
{% endhint %}

### Troubleshooting

| Symptom | Cause | Solution |
|---------|-------|----------|
| Helm install timeout | Database connection failed | Verify `POSTGRES_HOST`, `REDIS_HOST` values |
| Pod ImagePullBackOff | NGC authentication failed | Check `NGC_API_KEY` in nvcr-secret |
| osmo-service CrashLoop | Database password mismatch | Verify db-secret contents |
