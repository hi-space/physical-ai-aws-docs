# 1. Infrastructure Deployment (CDK)

Use AWS CDK (Cloud Development Kit) to provision the cloud infrastructure for OSMO in one step. Instead of manually creating resources in the AWS console, a single command creates your entire environment.

**OSMO requires the following infrastructure:**
- **EKS (Kubernetes)** — Where OSMO services and workflow Pods run
- **RDS (PostgreSQL)** — Database that stores workflow metadata and user information
- **ElastiCache (Redis)** — Message broker that manages workflow job queues
- **S3** — Object storage for training datasets and workflow logs

### Prerequisites

* AWS Account — Recommended region: `us-west-2`
* Check GPU instance service quotas — AWS Console → [Service Quotas](https://console.aws.amazon.com/servicequotas/) → EC2 → `Running On-Demand G and VT instances` to confirm you have sufficient vCPU capacity
  * g6e.12xlarge = 48 vCPU (Training nodes)
  * g5.12xlarge = 48 vCPU (Simulation nodes)

{% hint style="warning" %}
Insufficient GPU instance quota will prevent nodes from provisioning. Verify your quota in Service Quotas before deploying.
{% endhint %}

### 1.1 Environment Setup

```bash
# Clone the repository
git clone --depth 1 https://github.com/hi-space/aws-physical-ai-recipes.git ~/aws-physical-ai-recipes

# Set up CDK project
cd ~/aws-physical-ai-recipes/osmo/cdk
npm install

# Verify tools
aws --version
aws sts get-caller-identity   # Verify current AWS account
node --version    # >= 18
npx cdk --version # >= 2.x
kubectl version --client
helm version
```

---

### 1.2 CDK Bootstrap (One-time)

Run bootstrap on first CDK use in this region:

```bash
npx cdk bootstrap aws://$(aws sts get-caller-identity --query Account --output text)/us-west-2
```

---

### 1.3 Infrastructure Deployment (~20 minutes)

```bash
npx cdk deploy --context region=us-west-2 --require-approval never
```

{% hint style="info" %}
Deployment takes approximately 20 minutes. EKS cluster creation takes ~10 minutes, RDS creation takes ~8 minutes.
{% endhint %}

<details>

<summary>Infrastructure Created by CDK</summary>

| Category | Resource | Description |
|----------|----------|-------------|
| Networking | VPC, 2x Public/Private Subnets | Multi-AZ high availability |
| Networking | NAT Gateway, Internet Gateway | Private subnet outbound access |
| EKS | Cluster (v1.30) | Kubernetes control plane |
| EKS | System Node Group (m5.xlarge ×2) | OSMO service workloads |
| EKS | GPU-Train Node Group (g6e.12xlarge, 0~4) | GR00T training, 4×L40S GPUs |
| EKS | GPU-Sim Node Group (g5.12xlarge, 0~8) | Isaac Sim, 4×A10G GPUs |
| EKS | Addons (EBS CSI, Secrets Store CSI) | Storage and secrets management |
| Data | RDS PostgreSQL (db.t3.medium) | OSMO metadata storage |
| Data | ElastiCache Redis (cache.t3.medium) | Job queues |
| Data | S3 Bucket (Intelligent Tiering) | Workflow data/logs |
| Security | Secrets Manager | Database credential management |
| IAM | Cluster Role, Node Role | EKS permissions |

</details>

### 1.4 Verify Deployment Completion

```bash
# Verify all three node groups are created
aws eks list-nodegroups --cluster-name osmo-eks --region us-west-2
```

**Expected output:**

```json
{
    "nodegroups": ["gpu-sim", "gpu-train", "system"]
}
```

{% hint style="success" %}
If you see all three node groups, deployment succeeded. Proceed to the next step.
{% endhint %}

### 1.5 Deployed Resources Summary

| Resource | Specification | Purpose |
|----------|---------------|---------|
| EKS Cluster | Kubernetes v1.30 | OSMO services and workflow runtime |
| System Node Group | m5.xlarge × 2 | OSMO services, Kai Scheduler |
| GPU-Train Node Group | g6e.12xlarge (4×L40S), 0~4 | GR00T model training |
| GPU-Sim Node Group | g5.12xlarge (4×A10G), 0~8 | Isaac Sim simulation |
| RDS PostgreSQL | db.t3.medium | OSMO metadata storage |
| ElastiCache Redis | cache.t3.medium | Job queue management |
| S3 Bucket | Intelligent Tiering | Workflow data/logs |

{% hint style="info" %}
GPU node groups are configured with `desiredSize=0`, so no costs are incurred at rest. Manually scale up when running workflows.
{% endhint %}

### Troubleshooting

| Symptom | Cause | Solution |
|---------|-------|----------|
| `osmo-db-secret already exists` | Leftover secret from previous deployment | `aws secretsmanager delete-secret --secret-id osmo-db-secret --force-delete-without-recovery` |
| ROLLBACK_COMPLETE status | Resource creation failed and rolled back | `aws cloudformation delete-stack --stack-name Osmo` then redeploy |
| Deployment waits >20 minutes | RDS creation takes time | Normal. Check progress in CloudFormation console |
| `InsufficientInstanceCapacity` | GPU capacity exhausted in region | Use different instance type or region |
